简历上是 `bosprimigenious@bupt.edu.cn`。站点 Get Started 和页脚是 `bosprimigenious@foxmail.com`。两封都是我的。学校那封印在 PDF 上，跟北邮计算机、47/452 放在同一张纸里，给要校园邮箱的场合。站点对外联系目前用 foxmail。`_config.yml` 的 `contact_note`、`footer_text`，`_data/socials.yml` 的 `email`，首页和联系页的 `mailto:`，都指向 foxmail。GitHub 用户名是 `@bosprimigenious`。电话不放站点。

两封并存，是因为读者不一样。教务、实验室、需要校园身份的申请，走 bupt.edu.cn。从个人站点进来的人，包括看完汉服首页想问项目的，走 foxmail。我自己每天会开的，也是站点上这封。校园邮箱有时要校园网或特定登录，外人不稳。不稳的不要当站点主按钮。主按钮写 Get Started，链到 foxmail，是故意的。故意不等于简历写错。简历继续写校园邮箱。两封都要能收到。收不到的那封，等于公开了一个陷阱。

改联系方式的话，页脚、按钮、简历、socials、folio 里那些静态 html，要一起改。只改一处会有人寄到空邮箱。空邮箱比写错奖项更难发现：奖项读者会对照故事页，邮件寄出去没有回执，我不知道有人试过。所以改邮箱是破坏性操作：先列出所有出现处，再改，再在本地搜一遍旧地址。搜要用仓库内搜索，cwd 在 `bosprimigenious.github.io`。不要在 `$HOME` 搜，会把旧备份、MC 服笔记、别的仓里的测试账号算进来。MC 那篇里出现过 foxmail，那是游戏服登录备注，不是站点联系政策。政策以 `_config.yml` 和 about 页按钮为准。

电话不放，是同一类选择。简历 typst 若给需要电话的场合留了号码，PDF 可以带。站点不带。展板 A-53 也不印电话。展上能给的是项目名和能当场指到的系统，要联系，事后邮件。邮件写得清，比当场念一串数字少抄错。抄错电话，对方会打到别人那里。抄错邮件，最多弹回。弹回还能再试。站点少一个电话，也少一块要和 typst 同步的字段。字段越少，首页那句竞赛数字越不容易被挤乱。

课赛期间最容易漏改。奖项更新时人在改 `resume.typ` 和 `_stories`，邮箱那一行手滑成只改 PDF。PDF 发出去，网站还是旧的，或者反过来。我给自己的检查是：发任何带联系方式的材料前，打开 `127.0.0.1:4000` 点一次 Get Started，看邮件客户端弹出的地址是不是当前要用的那封。弹出 foxmail，就确认站点策略没变。若某次必须改成校园邮箱当主按钮，要把约好的所有入口一起改，并在这篇的事实失效时重写这篇。现在这篇的事实是：简历 bupt，站点 foxmail，电话不放。

两封都要自己会收。毕业或校园邮箱政策变动时，bupt 那封可能先失效。失效之前，简历源要改，发出去的 PDF 要换。站点不一定换。站点已经独立在 foxmail 上。独立是为了这个域名能在课设仓、国创仓、训练仓之外，仍有一个能收到信的入口。入口不承担奖项解释。奖项看故事页。入口只承担：人写了信，我能看见。能看见，才谈得上把仓库路径、演示是否能跑、数字是否指回 typst 讲清楚。看不见，上面那些页等于对空气开放。对空气开放也可以，只是不要假装有联系方式。有，就维持两封都活着，公开其中站点这一封。
## 改联系方式要三处一起

页脚、Get Started 按钮、简历 typst，三处对同一件事。只改站点，会有人寄到空邮箱。只改简历，点按钮的人还走 foxmail。电话继续不放站点。对外联系目前用站点上的 foxmail。两封都是我的，不是两个身份。
## 不要把电话「顺便」放回来

简历 PDF 给需要电话的场合。站点是公开的 git。公开 git 里放手机号，历史删不干净。Get Started 继续走邮件。有人问电话，私下给，不写进 `_config.yml` 的 contact_note。
## 两封邮箱不是两个身份

简历用 bupt.edu.cn，站点用 foxmail，都是张恒基。对外联系目前走站点按钮。有人从简历邮件回，我也收。不要在某一页偷偷换成第三封。第三封会让前两封变成死信。死信比没有联系方式更糟，因为看起来像还能寄到。
页脚那行邮件和按钮上的邮件必须同一封。同一封才能在公开 git 里长期留着。
有人从 GitHub 个人页点进来，走的是站点按钮。按钮坏了等于公开联系方式坏了。坏了先修按钮，不要临时把电话写进 README。
公开联系方式坏了要当天修，不要拖到下一周的课设里。
