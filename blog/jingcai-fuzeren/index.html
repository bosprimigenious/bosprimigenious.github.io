负责人三个字

京彩大创。全市赛审的是人加作品。

1 min · contest · textguard

评委问「谁负责」的时候，队伍往我这边看了一眼。第五届「京彩大创」北京大学生创新创业大赛，审的不只是代码。团队、进度、风险要能放在一张表上。我是张恒基，TextGuard / 文臻卫士的项目总负责人。负责人三个字在简历上好看。在这张全市的桌子上，意思是没接住的问题都先问你。

全市赛并不熟

大创两个字在学校里很熟。全市赛并不熟。校内答辩问实现，京彩问可持续。可持续听起来空，落到问题上却很硬：误伤怎么办、报告谁来用、和已有查重差在哪、三个月后谁还在维护。某一晚的 demo 再漂亮，也回答不了三个月后。

中文 AI 生成文本检测听起来新。新，会让评委先好奇，再立刻要落地。落地的第一问几乎总是误伤。把人写的判成机器，报告要给人看，给人看的东西不能只有一个分数。解释和样本对照在京彩不是装饰，是负责人必须能指着界面讲的部分。

我把风险表写得很短：误伤、超时、空结果、权限、没人维护。短，是因为长表没人在答辩里听完。短完，每一条都要有对应的界面或流程。对应不上的风险，不要写。写了就是给评委递枪。递枪这件事我在计设全国赛已经吃过一次，京彩不能再吃。

进度不是心情

负责人要能说出进度停在哪。停在「模型还在调」是心情。停在「报告导出缺签字字段、筛选在空结果时没有提示」，才是进度。京彩的材料里有一页时间表。时间表上的节点必须能对上仓库里的提交，对不上就不要印。印了，评委会问上周那一项为什么还是灰色。

团队分工也要经得住问。问到前端，我不能把 React 页面说成「有同学在做」就结束。问到接口，我不能把 FastAPI 说成「封装了一层」就结束。总负责人不是每一行代码都自己写，但是每一行被问到的代码都要知道它在哪条链上。不知道，问题会在你脸上停几秒。几秒在全市赛里很长。

TextGuard 拟申报大创。预期产出论文、软著与专利。预期两个字还在，京彩的场里就不能说已经有。已经有和正在做，评委分得清。我把「预期」留在材料的将来时里，把已经能打开的部分留在演示里。打开的部分包括识别、解释、报告导出。导出如果只是 PDF 外壳，会被问字段从哪来。

和查重差在哪

评委里一定有人用过查重。差在哪，要说得像一句能被记下来的话。查重看像不像已有文献。我们看像不像机器写的。两件事都可能产出一份报告，报告的使用者 overlapping 很高，判据完全不同。混着讲，项目会变成「又一个查重」。又一个查重在全市大创里没有位置。

我在京彩把这句话放在比较靠前的位置。靠前，是因为后面的技术细节会把评委拖进模型。拖进模型之后，再回来讲使用者就晚了。使用者是老师、教务、要签字的人。他们不读 JSON。负责人要替他们把报告变成能签字的东西。变成之前，先承认误伤。承认完，才有资格谈可持续。

三等奖是全市名单里能印出来的一档。上面还有更高。我们没有拿最高，拿到的是：这个项目被北京市的大创赛认下一截。认下之后，才有底气继续把平台做到 textguard.site。底气不是证书给的，是当场那些没接住又补上的问题给的。

风险表上「没人维护」这一条最不好看，也最常被问。评委听过太多「我们会一直做」。一直做没有时间点。我把三个月内还在仓库里的人、还要交的报告字段、还要修的超时，写成能对上提交记录的句子。对不上提交的句子，当场删。删完表更短。短表在全市赛里比长愿景经得住问。经得住问，负责人三个字才有着落。着落不在证书抬头，在你能不能把灰色的节点说成灰色。

没接住的先问你

我收到的限制跟身份绑在一起：总负责人不能把没准备的问题转给旁边的人再装作自己在听。转一次，评委就知道这张表上的风险不是你写的。京彩三等认下的是人和作品的一截，不是我个人把全栈都做完。全栈是 Python / FastAPI 加 React / TypeScript，官网后来挂在 textguard.site。挂上去之前，先过的是这张要你签字认领问题的桌子。

签字认领还有一句时态：拟申报大创，预期论文、软著、专利。预期还在，京彩的话术里就不能出现「已经授权」。已经授权和正在写材料，评委分得清。分得清的人面前，我把能打开的识别、解释、导出走完，把打不开的证书留在将来时。将来时不好听。不好听比假装已有安全。安全的负责人，至少不会在全市赛上把项目的时间线说断。
